01What a mod actually is here

A mod is a folder the game reads on startup. The Studio writes it for you, and it contains a small set of cooked files:

<game>\SWZeroCompany\Mods\YourMod\
    YourMod.uplugin
    AssetRegistry.bin
    Content\Paks\YourMod_P.pak
    Content\Paks\YourMod_P.ucas
    Content\Paks\YourMod_P.utoc

The game's own mod runtime finds that folder and mounts it at a higher priority than the base game, which is what lets a mod add parts and replace assets. Nothing belonging to the game is overwritten on disk. Removing the folder removes the mod completely.

There are two kinds of thing you can put in one:

KindWhat it does
PartAdds something new to the game — a helmet, a torso, a specialisation. Built by copying an existing part and changing it.
OverrideShips a changed copy of one of the game's own assets under its own name. This is how a locked specialisation or weapon gets opened up.

Most of what you will do is parts. Overrides are section 11.

02First run and the window

The first time you open the Studio it finds your Zero Company install by itself, reads the data-layout file it ships with, and remembers where the game is. That is asked once. If it cannot find the game, point it at the folder containing SWZeroCompany.

Every launch after that it checks the game against the file it ships with, and warns you if the game has been patched since. That warning matters: the tool reads the game's data through that file, and against a newer build it does not fail — it reads wrong values, silently. If you see it, expect names, icons and slots to be unreliable until a new one is available.

The window

PanelWhat it is for
AssetsThe raw file tree of the game and of every mod you have installed — see “Finding your own mod” below, because it is not where you would guess. You can open your own mod's mesh in the viewport from here without launching the game.
ViewportPreviews whatever mesh you click. Drag to orbit.
DetailsThe rig and asset information for whatever is loaded.
LogWhat the tool is doing. Read it when something is unexpected.

Along the bottom is the tab strip. The two that matter for modding are Parts (find something) and Mod (change it and build it).

Finding your own mod in the Assets tree

Press “Show its files” on the Mod tab, next to Install. It finds your mod's own packages and lists them in the Assets panel. That is the answer — you do not need to know the path.

The rest of this is why, and only worth reading if you are curious. There is a node at the top of the tree named after each installed mod, and it is almost empty: the plugin descriptor, a registry, three small files, none of your artwork. Everything real is cooked into the game's path space instead, at

SWZeroCompany
  Content
    Game
      Customizations
        Mods
          YourMod
            CPD_Mod_YourPart.uasset      the part
            SK_....uasset                the mesh, if it carries its own
            MI_....uasset                the material
            T_....uasset / .ubulk        the textures

Which is four levels down and named after the game, not after you — so nobody would find it by looking. Hence the button. Typing your mod's name into Search paths… does the same thing by hand.

You can preview it

Click the mesh and it loads in the viewport like any game asset — your own copy, with your own textures on it. That is a real read-back of what you shipped, not a preview of what you asked for, so it is worth doing before you launch the game.

Reload after installing

Containers are mounted once, at startup. A mod you have just built and installed is not in the tree until the game is read again — Settings → Reload game. Without that it looks like the install did nothing.

It looks for updates, and you can stop it

Once per run the Studio asks GitHub whether a newer release exists, and says so beside the credit in the menu bar if there is one. It sends nothing about you or your mods — it reads one public page and compares a version number. About → Look for a newer version when this starts turns it off, and it stays off.

03The core loop: duplicate a part

Nearly every mod starts by copying something the game already has. You do not build a part from nothing — you take one that works and change the bits you want.

  E -- yes --> F["Install

  1. Find it in the Parts tab Type into the filter — a name, a character, a word from the menu. Each row shows the game's own thumbnail, so you are looking at the same picture the game shows you.
  2. Press “Use as a mod part” This stages a copy. It carries across the mesh, the icon, the slot, whether it hides the head, and — importantly — the original part as its template.
  3. Switch to the Mod tab and accept it The staged part appears with an Add / Discard prompt. If you have no mod open yet, name one and press Create first.
  4. Change what you want At minimum give it a name people will see in the menu. Everything else has a sensible default.
  5. Build, then Install Build writes the files and immediately reads them back. Install is only offered if that read-back was clean.
Finding things in a list of eleven hundred

The Parts list is grouped into fold-away sections, in the order you would dress a character — Headwear, Tops, Armwear, Lower body, Boots, then everything else. Collapse all puts the whole catalogue on one screen, which is the fastest way to see what kind of thing exists before you go looking for one.

Where a name is genuinely ambiguous the row says why. Six entries called “ARC Trooper Phase II” are the same helmet in different colourways, and each row carries the part of its asset name that differs — base, TintA, TintB — so you can tell them apart without opening each one.

Why the template matters

A part is more than a mesh. It carries a base class and a set of fragments — the voice filter, the ability list, the attribute tables. Copying the part you picked keeps all of that. An earlier version of this tool took only the mesh and then guessed at a base, and a clone helmet came back built on a Mandalorian part: right geometry, no clone voice filter. Pressing “Use as a mod part” sets the template for you, which is why it is better than adding a blank part and filling in a mesh path.

04Worked example: Rex's armour for everyone

This is the thing most people want first, and it is worth explaining why it works, because the reason is not what most people assume.

Captain Rex's armour exists in the game as six ordinary outfit parts:

CPD_H_Outfit_CaptainRexA_HELM     Helmet
CPD_H_Outfit_CaptainRexA_TORS     Torso
CPD_H_Outfit_CaptainRexA_ARMS     Arms
CPD_H_Outfit_CaptainRexA_LEGS     Legs
CPD_H_Outfit_CaptainRexA_BOOT     Boots
CPD_H_Outfit_CaptainRexA_PACK     Pack
The key fact

Those parts are not locked to Rex. They carry no character restriction at all. What keeps them out of your menu is a development gate — and a copy does not inherit that gate, because the copy is registered under its own name with the gate tags stripped. So duplicating them is genuinely all it takes.

Which makes the recipe short:

  1. Create a mod Mod tab → type a name (say RexArmour) → Create mod.
  2. Filter the Parts tab for CaptainRexA All six pieces come up together.
  3. Use each one as a mod part One at a time. Six parts, six presses. Each lands in your mod with its slot and mesh already correct.
  4. Name them for the menu They default to “… (Mod)”. Something like “501st Captain — Helmet” reads better in game.
  5. Build and install Then start the game and look in the armoury. Every humanoid character can wear them — Hawks included — because nothing in the copy says otherwise.

Parts that are locked to a character

Some parts genuinely are restricted — heads, hair, and hero gear kits. Hawks has 32 such parts, Tel-Rea 24, Cly 16. They carry a name tag like br.Customization.Part.Character.Info.Name.CaptainRex, and a copy does inherit it. The build tells you when that happens:

CPD_Mod_Something: restricted to CaptainRex
                   by the template it was built from

Stripping that tag is what frees the part, and the part editor has a Remove tags box for exactly this. It lists the tags the template actually carries, so you pick the name tag out of a list rather than typing fifty characters of dotted namespace. The build then confirms it: “unlocked for everyone”.

Going the other way

For character restricts a part to one person. Choosing a name writes that character's tag onto the copy and takes any other one off, so it means exactly them. Leave it on everyone unless you specifically want a piece only one character can wear.

These are separate

Setting For character to everyone does not remove an inherited restriction — it just does not add one. If your copy came from a hero's own gear, use Remove tags to take their name tag off.

06Importing your own mesh

In the part editor, open My own mesh and press Browse. The popup has an Import an FBX… button that copies your file into ModSource/Meshes and selects it — the folder is created for you. Files already in that folder are listed alongside.

Requirements

  • Binary FBX. Not ASCII.
  • Skinned to the bones the part already uses. A weight on any other bone is dropped, and the build tells you which bones it dropped.
  • Keep the part's slot. A torso mesh in a helmet slot will equip in the helmet slot and look exactly as wrong as that sounds.
Why the bone list matters

Every humanoid part in this game is skinned to the same skeleton. That is what makes Rex's torso wearable by Hawks in the first place, and it is what makes your own mesh wearable by anybody — provided you weighted it to bones that exist on that skeleton. Export the part you are replacing first, use its rig as your reference, and the weights land where the game expects them.

Heads keep their facial animation — if you keep the vertex count

A head is not like the other slots. Beside its geometry it carries several hundred morph targets: the per-vertex deltas that are every expression the character can make. They are stored as compressed deltas addressed by vertex number, which means they only make sense against the exact vertices they were built for.

So the Studio applies one rule, and it is worth designing around:

  • Same vertex count as the head you started from — the expressions are carried through untouched. This is what you get if you export the head, move its vertices about, and bring it back. The face still acts.
  • Any other count — the deltas would point at vertices that no longer exist, so they are dropped. The head renders correctly and is completely still. The build says so in as many words; it is never silent.

If the face matters, edit the vertices of an existing head rather than modelling a new one. Adding or removing a single vertex costs you every expression, and nothing about the result looks wrong until the character tries to speak.

Only the closest level of detail carries expressions, in the game's own heads as much as in yours — so a face that stops animating at a distance is the game working normally, not your mod.

Importing a mesh switches on Carry my own copy of the mesh automatically, because your geometry has to live somewhere and it is not going in the game's files.

Garments that are several pieces

Some clothing dresses more than the slot it sits in. Clone Commando armour is one part, in the Torso slot, and wearing it replaces your boots, legs and arms as well — and adds a backpack. Inside, that part is not one mesh but five, one per body region, and it takes over the other slots so nothing you had chosen shows through.

When you pick a part like that, the part editor says so: “This garment is 5 pieces”, with a row for each — BOOT, TORS, PACK, LEGS, ARMS. Every piece starts out pointing at the game's own mesh, so a freshly staged garment is the garment you picked, unchanged. Open a row to give that piece your own mesh or your own imported file.

A piece you leave alone keeps the game's geometry. Replacing one piece of five is one row, not five. If you only want to redo the backpack, open PACK and leave the rest.

The parts browser marks these too: its mesh table gains a Piece column, and the header reads “7 across 5 pieces” rather than listing seven meshes as though they were seven body-type variants of one garment.

One garment, one entry — or several parts?

A garment like this is one part in one slot, so the game gives it one name and one picture however many pieces it wears. It takes over the other slots and greys them out, so those have nothing to name. The game's own Clone Commando is built exactly that way.

That is a choice rather than a limit, and the other option is worth knowing:

One multi-piece partSeparate parts, one per slot
A single pick that dresses the whole character.One pick each — arms, legs, boots, torso.
One name, one icon.Each gets its own name and icon.
The other slots are locked, so it is always worn complete.The player can mix your arms with anybody's torso.
Right for a suit of armour that is a set.Right for pieces meant to be combined.

To build the second, do not use the whole-body template at all: copy the game's own per-region parts instead — there is a separate Boots, Legs, Arms and Torso part for each armour kit — and give each one its own name, icon and mesh.

Give every piece the same scale and axes. A model split across several files is aligned in your modelling tool and exported from one scene — the pieces have no offset relative to each other here, so if they line up in Max they line up in game, and if they do not, they will not.

If you name a piece the template does not have, the editor says so in red and lists the pieces it does have, and the build refuses to guess — an entry aimed at nothing is never quietly applied to some other piece.

Getting the game's models into Blender

Before you can replace a mesh you need the original to work against — its shape, its scale, and above all its rig, because your model has to be weighted to bones the game already has. The Blender add-on that ships with this tool does that from inside Blender: browse the game, click an asset, and it arrives in your scene with its skeleton, its skin weights and its materials already set up.

Install it from Plugins in the menu bar. Point it at your Blender installation and it copies the add-on into place. Blender itself asks you to switch it on the first time — open Edit › Preferences › Add-ons, search for Zero Company, and tick it. That last step cannot be done for you; Blender keeps its list of enabled add-ons inside its own preferences file.

Then, in Blender, press N in the 3D viewport to open the sidebar and pick the Zero Company tab.

  1. Scan Game, once. It reads what the game contains and remembers it, so the list is instant from then on.
  2. Pick a category — Characters, Weapons or Vehicles — and narrow it further by collection if you want, or just type in the search box.
  3. Import Selected. A couple of seconds later the model is in your scene.

What arrives is the real thing: the mesh, an armature with the game's own bone names, the vertex groups that bind them, and materials with the game's textures already connected. Export your edited version as FBX and bring it back through My own mesh above.

Two textures come in switched off on purpose. The mask and the tint mask are loaded onto the material and left unconnected, labelled with the names the game uses for them. They pack several different things into one image, and wiring them up as though they were ordinary maps would look right and be wrong. They are there for when you know what you want from them.

Level scenery is left out of the list. It is four fifths of everything in the game, none of it is what somebody opens this to get, and the pieces are very heavy.

07Replacing textures

Open the Textures section of the part editor. It lists the textures this part actually wears, read from the mesh's own material — not a guess, and not a list of every texture in the game.

  1. Choose a mesh first The material is what names the textures, so until there is a mesh there is nothing to list.
  2. Pick the slot you want to change Each row shows the texture's name, its size and its format. Hover for the full details.
  3. Point it at your own image Press Browse on that row, then Import… to copy an image in. Leave a row alone to keep the game's own.
Match the shape

Keep your replacement the same dimensions as the original unless you know why you are changing them. The size and format are shown on each row precisely so you can match them.

08Icons

Press Browse beside the Icon field. The popup has two halves:

  • Your own icons, with an Import a PNG or TGA… button. That copies the file you choose into ModSource/Icons beside your mods, creates the folder if it does not exist, and selects it. You never have to find the folder yourself.
  • The game's own — a grid of the actual pictures, not a list of names, filtered to the slot you are working in.

Duplicating a part brings its icon with it, so this is optional. Change it when you have changed the look enough that the original picture would mislead.

09Building, and what the check catches

One button, Build and install: the mod is built in a scratch location you never see, read back and checked, and — only if it came back clean — written into the game's Mods folder as its own mod folder. The panel says where it went. If the check fails, nothing is installed. If the game is running and holding its old copy open, the build is kept, the panel says so, and Install finishes the job once the game is closed.

Press Build mod. The tool writes the mod's files and then immediately reads them back out and inspects them. That read-back is not a formality — it is the difference between a mod that works and one that installs cleanly and does nothing.

What it checks

  • Unlocked for everyone. A gate inherited from the template means the player will never see the part.
  • Offered to every character. An inherited character restriction, reported unless you said you expected one.
  • Carries a slot tag. Without one, nothing will offer it.
  • Registered under its own name. A part registered under another asset's name collides with it and loses — which looks exactly like a mod that never installed.
  • Takes over everything its template does. A missing override slot means the part half-equips.
The gate this gives you

Install is disabled unless the read-back is clean. A mod that failed its own checks cannot reach the game by that route at all. If Install is greyed out, read the line above it — it already says what is wrong.

10Installing and removing

Close the game first. A running game holds its files open and the install will fail part-way.

Press Install into the game. The Studio finds the game's own Mods folder, writes your mod's folder into it, and tells you where it went. Nothing belonging to the game or to another mod is touched, so your mod can sit beside anyone else's.

Take it out removes it again, completely.

To look at what you just installed, press Settings → Reload game and then find it in the Assets tree under Customizations/Mods/. Nothing appears there until you reload, because containers are mounted at startup.

Before it copies anything, the Studio checks for clashes and reports them in plain terms:

MessageMeaning
replacesYour override deliberately replaces a game asset. That is the mechanism working, not a fault.
CLOBBERSYou are replacing a game asset that no override declares. This one is a real problem.
also defined byAnother installed mod defines the same package. Only one of them will apply.
Two mods, one registry

If another installed mod ships its own asset registry, only one can win — and the winner has no record of the other's parts, so one mod's parts vanish entirely from the game. The install says so when it happens. Remove one, or rebuild the other after this one.

“Can I just drop the pak in ~mods?”

This is the first thing most Unreal modders try, because it is how nearly every other UE5 game takes a mod. It is worth knowing exactly what happens, because the honest answer is not simply “no”.

A mod built here is a folder, and it goes in SWZeroCompany\Mods\. The three container files inside it are part of that folder — they are not a mod on their own, and pulling them out to put somewhere else takes the mod apart.

Two ways this goes wrong

A lone .pak never mounts — anywhere. The .pak, .ucas and .utoc are one container in three files. Copy only the .pak, as people do out of habit from older games, and nothing loads at all. That is true in ~mods, in Content\Paks and in the Mods folder alike.

Two mods in ~mods clobber each other. A mod in that older shape has to carry a copy of the whole game's asset registry with its own entries added, and every mod writes it to the same path. Install two and only one registry survives — so the loser's parts are completely absent from the game while its files sit there looking perfectly installed. Nothing announces it.

That second point is the whole reason for the folder. A mod in Mods\ carries its own small registry inside its own folder and shares nothing with anybody, so ten can be installed at once and none can stand on another. The container is still marked _P, so an override still wins against the game's own files — you give up nothing by using it.

Tell the people who install your mod. They will reach for ~mods too. “Unzip the folder into SWZeroCompany\Mods” is the whole instruction, and it saves the message that begins “I installed it and nothing happened”.

11Sharing your mod, and what that protects

Once your mod is a folder somebody else can install, it is worth knowing exactly what you have handed them. The short version: the contents are readable, and nothing here changes that. Everything below is the detail behind that sentence, because a modder deciding how much work to put into a piece deserves the real answer rather than a comfortable one.

There is no way to encrypt a mod

Unreal can encrypt the containers a game ships. It works by looking up a key that was built into the game's own executable, and Zero Company shipped without one — nothing in the game is encrypted, so there is no key for a mod to use. A mod cannot add one either: registering a key means running code inside the game, which is exactly the kind of thing this tool exists to avoid needing.

An encrypted mod would therefore not be harder to open. It would fail to load.

And the idea does not survive even if the key existed. The game has to decrypt your mod in order to draw it, on the machine of the person you are protecting against — so the key travels with the content wherever it is kept. That is true of every game, not only this one. Free tools already read this game's files, and they will read your mod's the same way.

What the Mod Studio does about it

It refuses to be the easy path. That is a smaller claim than protection and it is the one that is actually true.

The studio shows every mod installed beside the game, so you can see what you have. A mod it did not build is shown with a padlock and a dimmed name, and three things are turned off for it:

What is refusedWhat happens instead
ExportThose files are left out, and the panel says how many it withheld and why. Nothing is skipped silently.
Use as a mod partThe button is greyed out, with the mod's name and its author under it.
Building from itSomeone else's part cannot become the template for yours.

Somebody determined to take your mesh will still take it, with a tool that has nothing to do with this one. What this stops is the easy version — the person who installed your mod, opened the official editor, saw your work in the tree and pressed a button. That road is short, and it is the only one anybody here can close.

Your name goes with it

The Author field on your mod is written into the file the game reads, and the studio shows it beside your mod's assets. It prevents nothing. It does mean a piece of your work that turns up somewhere else has a name attached to it, and that somebody copying it has to actively remove that name rather than simply not think about it.

How it knows which mods are yours

Two things, and either is enough:

  • You installed it from here. Every install is recorded, in your own settings rather than inside the mod — a marker written into a mod folder would travel with a copy of that folder and claim to be everyone's.
  • You have the project file. Any mod in your mods folder counts as yours, which covers one you built on another machine and brought across.
If your own mod comes up locked

That means this installation has neither record: no install and no project file. Open the project and install it again and it is yours from then on.

Which is the real reason to keep your project files. They are small, they are the only editable version of your mod, and a build output cannot be turned back into one.

12Overrides: changing the game's own assets

An override ships a changed copy of one of the game's assets under its own name. This is how you unlock a hero specialisation, open up a weapon, or rename something the game already has.

Add one with Add override, then pick the game asset with Browse.

ToolWhat it is for
New menu nameRenames the asset as the player sees it.
New descriptionReplaces both the short and the long description. The game's own markup works: <Bold>text</> and <Keyword id="UI.Keyword.ActionPoint">AP</> render exactly as they do on a shipped weapon.
Remove tagsTakes gate tags off. Removing a hero's name tag is what offers their specialisation to everyone. The picker lists the tags the target actually carries, so you cannot invent one.
Add tagsPuts tags on. Needed when removing a gate is not enough — some hero specs declare no slot tag of their own and need one added.
Rename namesRewrites a name everywhere it appears. Blunt: every use changes, so only use it for a name that means one thing.
Add a property it does not haveCreates a tag container the asset never carried. Everything else here edits something already present; this writes something new.
Re-point a namePoints references at a different name, with a count you predict. A soft object reference is two names — the asset path and the object name — so pointing one elsewhere usually needs two rows.

Replacing a model, a texture or an icon

An override can also carry your own art into the game's own asset. This is the difference between adding a helmet beside the game's and changing the helmet everybody already wears: nothing new appears in any menu, and every character wearing that piece wears yours.

Start where you would start anything else — find the part in Browse the game, and on Use this part… choose Replace it in the game rather than duplicating it. It lands in the mod you have open with the same three steps a duplicate has:

StepWhat goes in it
MeshYour FBX, with the same fit measurements and the same live preview a duplicate gets — your model on the game's own skeleton.
MaterialsOne field per texture the model wears, listed by name and size. Choosing a PNG or TGA shows it in the preview straight away.
IconThe picture the menu draws for it.

Each of those is a separate asset in the game, so the Studio quietly makes one override per file as you fill them in and takes them away again if you clear a field. That an armour piece is three or four packages is true and it is the tool's problem, not yours.

A replacement cannot be turned off in game

There is no menu entry to un-pick. Removing the mod puts the game's own asset back — but if you have equipped anything from a mod, unequip it and save before you remove the folder, or the save file will still name a package that is no longer there.

The rule that makes overrides work

The game keeps two copies of a part's tags: one in the asset itself, one in an index written when the game was built. The menu reads the display name from the asset and availability from the index. Change only the asset and you get a renamed part that is still locked. The Studio edits both for you — but it is why an override that “looks right” can still do nothing, and why the build's own comparison is worth reading.

13Changing the numbers: balance mods

Damage, range, critical chance, overwatch arc, reaction damage — every number on every weapon lives in a plain data table that the game reads while it is running. No Unreal, no Blueprint graph, no bytecode. A balance mod is a handful of edited numbers in a table, and the Studio can change any of them.

Getting there

Open a weapon in the Parts tab. Under Weapon specialisation you get its attribute table, and beneath that a button: Edit these numbers in a mod. That adds an override for the table to whichever mod you have open and drops you into the Mod tab with every row editable.

The New value box is yours. The Game column beside it is what the game ships, and it stays there while you work — an editor that shows only what you typed cannot answer “what was it before?”, which is where every balance change starts.

Rows you do not touch are not shipped at all. Typing a value back to the game's own removes it again, so a mod only ever carries the numbers you actually changed.

What you seeWhat it means
A row in green, with a reset buttonYou have changed it. Reset puts it back and drops it from the mod.
A row marked unsetThe game ships it as zero, and a zero is not written into the file at all. You can still give it a value — the Studio adds the property back for you — it is simply a larger edit than changing one.
The Min and Max columnsAnnotation, not limits. Rex's DC-17 ships a critical damage of 8 against a declared maximum of 2, so the Studio does not hold you to them either.

What the game actually reads

It reads the table. This is worth stating plainly because it is the one thing that makes the whole feature possible, and it was established the only way it could be — by shipping a mod and looking. Set a repeater's base damage to 88 and the armoury shows 90, the extra two coming from an attachment fitted to that weapon. Your number goes in at the bottom and the game's own modifiers stack on top, which is exactly what you want: the number you type is the number the game starts from.

One table can belong to several weapons

A table is named for a weapon type, not for a character. Attributes_RangedWeap_BlasterPistol_Default is the standard-issue pistol for everyone who carries one; Rex's DC-17 has its own. Before you change a number, look at which table you are in — the Studio shows its name above the rows — because “buff the pistol” and “buff my pistol” are different tables.

Renaming, and saying what you changed

A rebalanced weapon that still calls itself by the stock name and describes itself with the stock text is only half a mod. Both are on the same override, in New menu name and New description, and both work in game.

They are worth a note, because what you are editing is not what you might expect. A display name is not a string stored on the part — it is a reference to an entry in a shared string table, which is then looked up again in the game's translation file. Two indirections away from the asset anybody would think to edit. The Studio sidesteps both by replacing the whole thing with a literal, so your text is shown as written and no translation can override it. You do not have to do anything about that; it is just why the name in the file and the name on screen are not obviously the same thing.

The markup works

Descriptions accept the game's own rich text. <Bold>Base Damage</> comes out bold, and <Keyword id="UI.Keyword.ActionPoint">AP</> comes out as a keyword link, exactly as on a weapon the game shipped. ASCII only.

Abilities

Under the stats, a weapon lists the abilities it grants — its standard shot, its overwatch, whatever else it can do. Click one and the Studio opens that asset, so you can see what it is before deciding whether it is the thing you actually want to change.

14Changing what an ability does

Firestorm's damage, how long Disoriented lasts, how much accuracy it takes off you — all of it is data, and none of it needs the game unpacking. Open the Browse the game tab and press Abilities.

Find the ability, and the page shows you the whole of it: what the game calls it, its description as a player reads it, and every number behind it. Then Change what it does puts the assets that hold those numbers into whichever mod you have open, and takes you there. Each one arrives with its numbers under Its numbers, laid out exactly like a weapon's stats — your value on the left, the game's on the right, and anything you leave alone is not shipped.

An ability is a signpost, not a number

A GA_ asset holds almost nothing. What it holds is a list of the effects it applies — GE_ assets — and each of those carries the actual magnitudes. Firestorm applies five. That is why one press can add several things to your mod, and why the page lists the ability and everything it applies together: what a person means by “Firestorm” is all of it, and hunting through five assets for one number is what used to send people to a command-line unpacker.

Three reasons a number will not do what you expect

These are the whole reason the page is worth reading rather than skipping to the boxes. The Studio marks each one on the row, so you never have to find out by shipping.

What you seeWhat it means
read elsewhere — a curve tableThe number in the asset is a fallback nobody reads; the real value is a row in a curve table. Changing it builds cleanly and does nothing in game.
read elsewhere — worked out another wayThe magnitude is derived from one of your attributes, handed in while the game runs, or computed by code. Same story: the number is there, it is editable, and it is ignored.
zero, not storedA cooked file leaves a zero out entirely, so there are no bytes to write over. The box is greyed out rather than hidden, so you can still see what the ability does.

Most damage in this game falls into the first two. That is not the Studio giving up — it is what the game's own files say, and knowing it before you spend an evening on a number is the point.

This is a replacement, not a copy

Everything here is an override. You are shipping the game's own ability with a different number in it, so every character who has that ability is affected, and nothing new appears in any menu. There is no way to give one squad member a stronger Firestorm this way — that would be a new ability, granted by a specialization of your own (section 15).

What is worth changing

Durations and stack counts are the reliable ones: how many turns a debuff lasts, how many stacks an ability applies, how much a flat modifier adds or takes away. GE_Disoriented takes 4 off accuracy and the box says so; type 25 and it takes 25.

15Making a specialization

A specialization is the class a recruit is — Assault, Scout, Padawan. It is a part in exactly the sense everything else here is a part, and it has no mesh whatsoever. What it has instead is a name, an icon, a few abilities granted outright, a starting gear kit, and a focus tree: three lines of ability tiers, seventeen rungs in all, which is what a player spends focus climbing.

Making one is the same loop as everything else. Open the Specs tab, find the specialization closest to what you want, and press Duplicate into a mod. All of it comes across — every ability, every rung, the gear kit — and you change the parts you want different. It arrives in whichever mod you have open, and the Studio takes you straight to it.

Copy the closest one, not the simplest one

Your copy inherits everything you do not change, so the template is doing most of the work. Start from the specialization whose tree shape and theme are nearest your idea, not from whichever one you happen to know best. A Force-flavoured class built on Padawan needs three edits; the same thing built on Assault needs seventeen.

What you can change

What it will not do, and tells you so

Two things are fixed by the specialization you copied, and the build reports them rather than quietly ignoring them:

  • The number of entries. You can change what an ability is, but not add a fourth granted ability or remove a rung. Those lists are a fixed length in the file, and growing one means rebuilding the asset rather than editing it.
  • A rung's level and focus cost. The editor shows them so you can see the shape of the tree you are working in; they are numbers buried inside the tree's own structure and are not reachable yet.

Choosing an ability

Every ability slot and every rung is a searchable list of all 826 abilities in the game, with the family each belongs to shown beside it. Pick one and the Studio writes the reference correctly.

This is why it is a list and not a text box

An ability reference is a full path, and the folder in it is not the one anybody would guess. GA_Firestorm lives under Gunslinger and GA_BullRush under Soldier — while the Assault specialization grants both of them. Typing these out from memory gets them wrong. If you do need something the list cannot reach, the full path is still editable at the bottom of the same panel.

Tiers have to match, and that part is on you

A line of the focus tree is a ladder of the same ability getting stronger: GA_Firestorm_T1 through T6. Replace all six with the six tiers of something else and it works. Replace one rung of six with a single-tier ability — most hero abilities are single-tier — and the remaining five rungs still grant the old one. Nothing is broken; it simply is not what you meant.

Rex and Anakin cannot be duplicated into a usable class

Their kits have no focus tree at all — zero lines, zero rungs. The picker draws a three-line tree and will not offer a specialization that cannot fill one, so a copy of a hero kit never appears however open you make its tags. Three separate attempts went into removing gates before that was measured. The Specs tab shows the rung count for exactly this reason: if it says zero, stop.

What does work is the other direction — put a hero's abilities into a copy of a real class. That is how “Jedi Knight” got made: Padawan's tree carrying Anakin's four abilities.

A hero's class is unlocked for you

Hero specializations carry their owner's name tag, and a plain copy would inherit it — giving you a brand-new class that only Tel-Rea can choose. Duplicating drops that tag, from both the asset and the record the menu actually filters on. Leaving Only for blank is all you have to do.

Why the identity tag stays the same

A duplicate keeps its template's identity tag, which looks like a mistake and is not. A specialization sharing that tag has been built, shipped and played: it appeared in the picker and the game's own recruit generator started rolling it onto new recruits. A freshly invented tag is one the game's tag table does not define, and nothing outside Unreal can register it — so it may simply resolve to nothing. Make it its own is there if you want to try; it is not the default because the default is the thing that is known to work.

There is no picker list to add yourself to

The game finds specializations by their slot tag in the asset record, not from a list of the eight it ships. Build one correctly and it is offered — and the recruit generator treats it as a first-class member of its own pool, which means recruits will turn up already wearing your class. Whether that is what you wanted is a design decision; it is not something that can currently be separated.

16Making a weapon

A weapon is not one asset. The Armoury lists a part; that names a gear kit, which names the weapon actor, which names the loadout, which names a type part carrying the weapon’s tag — and that tag is what picks the weapon’s meshes out of palettes shared by every weapon in the game. Five files and five mesh palettes, and on disk nothing says they belong together. The Weapons tab shows a weapon as one weapon, and does the copying for you.

Open the tab, pick the weapon closest to what you want, and press Duplicate into a mod. Every link is copied under your mod’s name and re-pointed at the others, a palette copy is made for each slot the weapon has a piece in, and the copy is routed onto a weapon class of its own. It arrives in whichever mod you have open. Nothing of the game’s is written over: the weapon you copied keeps every part it has, and yours stands beside it.

It gets its own shelf

A duplicate is not squeezed in beside the game’s own weapons of that class. It goes onto a Custom Longarm, Custom Rifle, Custom Pistol or Custom Repeater shelf, defined by a small mod called Custom Weapon Classes that this tool ships and installs for you the first time you need it. You can also give a weapon a shelf of its own, with a name you choose — “Bob’s Heavies” sits in the class list like any of the game’s.

It also keeps your weapons out of the game’s own lists, which is tidier for anyone who installs your mod: their Longarm shelf still holds the four the game shipped.

A long list sometimes draws a blank row, and it is not your mod

Once a weapon class holds eight or so, the Armoury will occasionally draw one row with no name and no picture. It is still selectable, and it still works. Scroll, or leave the screen and come back, and it will be a different row — or none.

That is the game’s own list reusing its row widgets: a row fades itself in with an animation, and one that gets reused without replaying it stays invisible. It happens on the game’s own weapon classes too, with no mods installed past the count. Nothing in your mod causes it and nothing in your mod can fix it — the tool says so at build time rather than letting you hunt for a fault that is not yours.

The choice that decides everything else: its type

Every weapon carries a type tag, and that tag is the key its meshes are stored under in the palettes. You get one decision, and the rest of this section follows from it.

Why this used to go wrong

The first DLT-20A turned up in game wearing another rifle’s barrel, sticking out of its own. That is the donor’s type working exactly as designed on a model that already had a barrel built into it. The opposite mistake — minting a type and expecting the game’s scopes to fit — produces attachments that vanish the moment they are equipped. Both were measured in game, both ways.

Imported your own gun? The attachments will not fit it

Keeping the donor’s type means the game’s twenty-one attachment pieces answer for your weapon — but every one of them was modelled and positioned for the gun you copied. On a re-skin that is exactly right. On a weapon whose mesh you have imported, it is not: the scope will sit where the donor’s scope sat, which on your model may be floating beside the barrel, buried inside it, or facing the wrong way.

Nothing warns you, because nothing is wrong — the game is fitting the piece it was told to fit. If you import a weapon mesh, plan on replacing the attachment meshes too, or on positioning yours so the donor’s pieces land where they should. Use my own on each attachment row is where that is done; there are twenty of them if you want the full set, and you can do as few as you like — the ones you leave alone keep the donor’s.

Column saysWhat it means

sharedThe 02–05s. One material and one texture set for every gun in the game. Only the mesh is per-weapon — and the mesh is what carries the position, which is why every gun has its own copy of each attachment even though they all look the same.
Painting a shared one is still safe

Your mod copies the material and the textures into its own folder and points its own mesh at the copies. The game’s Mods_SharedElements is never written to, so every other weapon keeps the paint it had. You should know a piece is shared before you paint it — that is what the column is for — but you are not going to break anybody else’s gun by doing it.

One model, or several? — and you must pick one

This is the part that costs people an evening, so it is worth being blunt about.

If you model the whole gun as one piece

Put it in Base 01 and empty every other 01 slot — Barrel, Stock, Cell, Scope, whichever your model already contains. Otherwise the weapon you copied lends you its barrel on top of the one you modelled, and you get both.

Emptying happens inside your mod’s own copy of that palette. The original weapon keeps all of its parts.

If you split the model into its slots

Model the receiver, barrel, stock and scope as separate objects in one scene, positioned where they belong on the finished gun, and export each one. Each goes into its own slot with Use my own. The game assembles them the way it assembles its own weapons.

  1. Export them all from the same scene They must share one origin and one scale. Each mesh carries its own position — there is no offset field anywhere — so alignment is done in your modelling tool, and only there.
  2. Do not export the pieces separately from different scenes They will land in the right slots at the wrong places, and nothing in the tool can tell you which one moved.
  3. Check the centres, not the sizes The build prints, for every piece, where it ended up against where the game puts its own. Matching centres means it is aligned. A different size is expected and fine — your barrel is not the donor’s barrel.

Splitting has a cost, and it is the type tag again

With a type of its own, a split model turns two harmlessly empty slots into eight that must each be filled. Your barrel is in Barrel 01, so it shows by default — but fit a Condenser and the slot points at the game’s Barrel 02 palette, which holds no entry for your weapon, and the barrel is not drawn at all. With the barrel welded into the body that never happened, because the body always shows.

Leaving them blank is a finished answer, not an unfinished one. A modification’s stats live on the modification, never on the mesh, so a player who fits a Condenser still gets everything it does — the gun simply does not change shape. Fill a slot only when you want that piece to be seen. The list counts them for you: “8 of 21 yours, 13 left blank”, and says the same thing above the rows.

If you do want them all, it is four more meshes per slot, each positioned for your gun.

The scale on your FBX is not always right

A mesh exported from a modelling tool carries a scale on its own node, and it is not always the one the game uses. If a piece comes out wildly wrong the build refuses the import, ships the game’s mesh instead of yours, and says what the file claims and what the game measures. Read that line: it names the number to set in Mesh scale.

What it also offers — “a scale of 188.313 would match its height exactly” — is right for one mesh replacing one mesh and wrong for a set. Taking that number for each piece of a split gun scales four pieces by four different amounts and pulls the model apart. For a set, one scale for all of them, and check the centres.

17What attachments do: changing a modification

The barrels, cells, scopes and stabilizers a player buys in the Black Market and fits in the Armoury. There are 64 of them — four styles per slot, four tiers per style — and what each one does is a single number on its ability asset. Attachments → What attachments do lists all 64 with that number beside them.

This is a different thing from the attachment list on a weapon you duplicated, in section 15. That one decides which piece appears on the gun when a modification is fitted. This one decides the +2 Critical Hit Damage.

Changing one

Type in the box. The faint number to its right is the game’s own, and reset puts it back; setting a box back to the game’s value by hand removes the change rather than shipping “2 becomes 2”. Put them all back clears the lot.

Percentages are typed as percentages. A chance stored as 0.06 shows as 6.0% and you type 15 for fifteen per cent. Which numbers are fractions is read from the game’s own data, not guessed from the size of the value.

Nothing here uses a modification up: it keeps its icon, its cost and its place in the Black Market.

Its name, and what it says

Click a modification’s name and a panel opens under it with what the Black Market calls it and the sentence under that. Leave a box empty to keep the game’s own, which is the grey text inside it. The list above updates to the name you gave, because that is what a player will see.

The description takes the game’s own rich text — <Bold>text</> and <Keyword id="UI.Keyword.CriticalHit">Critical Hit Damage</> — and it takes {effectDescription_1}, which the game fills in with the number you set above. Keep that in and the sentence stays true after you change the stat.

The same panel sets how rare it is — Common, Uncommon, Rare or Unique, which is what the Black Market uses to decide how it presents and stocks the modification — and what it costs and sells for, in credits. The two prices sit side by side because they are set against each other: a modification that sells for more than it costs is a credit press.

A modification is two assets, so this is two overrides

What it does lives on an ability; what it is called and what it costs live on a separate shop item, joined to the ability by name. The Studio edits them independently — change only the number and only the ability is touched — which is why the count beside What attachments do can go up by two when you change one modification completely.

Second numbers

Some modifications carry more than one. The Ion Modulator has a separate bonus against Ray Shields; the Balancing and Ergonomic stabilizers put a cap on the bonus they stack up. Those appear indented under the tier they belong to, labelled with the name the asset gives them. The description above the group says where each lands: it is the {effectDescription_2} in the sentence.

Tiers that say “inherited”

Four of the 64 do not carry the main number at all — Balancing T2 and T3, Ergonomic T2 and T3. They use the tier below’s and raise only their cap, and a cooked file does not write a value that has not changed. Nothing is wrong with them.

Press Give it one and the mod adds the property rather than writing over it, starting at the value the tier is using now. It is a larger edit than the others, which is why it is a button rather than a box.

One asset, every weapon

A modification is a single asset that every gun in the game reads. Change the Single Coil Condenser and it is changed for your weapons and for the game’s alike, on every save. That is usually the point of a balance mod; it is worth knowing before you halve something.

It also means two mods that edit the same modification collide, and the build’s clash check says so at install time.

The build proves the number, and you should read the line

The build log says “2 → 12, reads back 12 as a double at byte 1980”, and then again after the container is mounted: “its numbers read back: GameplayEffectModifer = 12”. Both are the asset being read, not the tool repeating its own intention — a stat is stored as an eight-byte number whose upper half looks exactly like a four-byte one, and an earlier version of this wrote into the middle of it, reported success, and produced 134,217,728.

18Making a recruit out of an enemy

The game fights you with battle droids and never lets you have one. You can hand one to the player: a B1, a B2 or a BX commando who joins the company, carries his own weapon, moves in his own animations and takes his turn like anyone else. None of it needs UE4SS, and none of it touches an asset the game ships.

Start on the Recruits tab. It lists the roster the game hires from, and every character the game has. Pick the enemy you want and press Add: the Studio copies what he is made of into your mod, gives him a name you can change, and opens his page. Everything after that is the boxes on that page.

The boxes, and what each one is really for

Also ship a weapon for the ArmouryA blaster in the Armoury that carries this droid's animation tables and his stance clips. Equip it on him and he aims, turns and fires as himself.

Separatists do not appear on the mission-ready screen

Your droid plays normally and shows up everywhere else, but the squad-select screen before a mission draws him as nothing at all. That screen does not show your characters the way the battlefield does: it renders a hologram, and the hologram is one fixed actor with a human body, with each character's customization applied on top of it. A droid's body is not in his customization — it is on his own pawn, on a skeleton that actor cannot wear — so there is nothing for it to draw.

It is cosmetic. He deploys, he fights, and he is on the field when the mission starts. Nothing in a mod reaches that screen, because the proxy it uses is a single asset the game picks by itself.

Joining without being hired

There is a second route, and it is unfinished. A campaign recipe can add a character outright, the way the story adds one, and a character who arrives that way never goes through the hiring pool and never has his class or weapon rolled away. The Studio can build it — a pawn class of your own, a copy of a story recruit recipe, and the recipe written into every chapter's arc — but no campaign has been played through on a sound build to confirm it, so it is off and out of the way under Advanced → Labs. Turn it on there if you want to try it, and expect to end a cycle in chapters two to six before anyone joins.

19Traps that cost real hours

  • Ids must be unique across installed mods. Not just within your mod. Two mods sharing an id cook to the same package path and one silently wins.
  • A helmet that does not hide the head renders the character's face and hair through the visor.
  • A mesh path without its .AssetName suffix imports as an empty pointer, and the part equips nothing at all.
  • “Restriction expected” does not restrict anything. It only tells the checker what you meant.
  • Edition and story gates travel with a copy. A development gate does not. If the build says your part is gated, it will not appear no matter how correct everything else is.
  • Close the game before installing. Every time.
  • Read the build log when something is odd. It reports what it changed, and the comparison names anything that changed which you did not ask for.

Weapons

  • A weapon model that already has a barrel needs the barrel slot emptied. Otherwise the weapon you copied lends you its own and you get two. Section 15.
  • A split model must come out of one scene. Each piece carries its own position — there is no offset field — so aligning them is done in your modelling tool and nowhere else.
  • Compare centres, not sizes. The build prints both. A piece of yours being a different size from the one it replaces is expected; a different centre is the misalignment.
  • “A scale of N would match its height exactly” is advice for one mesh, not for a set. Following it per-piece scales a split gun by a different number each time and pulls it apart.
  • A type of its own means blank slots, not the donor’s parts. Thirteen of twenty-one, on a typical weapon — and blank costs you nothing: the modification still gives its stats, the gun just does not change shape.
  • A blank-but-selectable row in a long weapon list is the game’s, not yours. Which row it is changes as you scroll. Section 15.
  • Your mod’s copies never touch the game’s art, shared attachment textures included. If something changed on a weapon you did not edit, it was not this.

Those ModSource folders are made for you the first time you import something, so you do not need to create them. A file left in a ModSource folder beside your mods folder is also found, which is the older layout from when mods lived inside an Unreal project.

The .json project file is plain text and safe to edit by hand — comments and fields the tool does not know are preserved. It is also the only way to reach the handful of things that have no button yet.
